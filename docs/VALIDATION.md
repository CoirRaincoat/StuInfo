## 2026-09-20 长按拖动测试时序修复

用户在 Windows 构建中遇到 `test_drag_multiple_and_autoscroll` 失败，200 ms 等待后拖动集合为空。检查发现应用的长按阈值为 180 ms，而旧测试仅留下 20 ms 余量。Linux 下通过在按下后约 120 ms 阻塞事件循环 140 ms，复现同样的空集合：旧等待返回时手柄仍按下，长按定时器剩余时间为 0，但回调尚未执行；继续处理事件后能正常进入两人拖动。[Qt 官方说明](https://doc.qt.io/qt-6/qtimer.html#accuracy-and-timer-resolution)明确计时器可能延后触发。

修复测试与截图脚本的等待条件：最多等待 2 秒，并在状态到达后立即继续，超时或取消仍失败，输出手柄、定时器与焦点状态。应用仍使用原有 180 ms 长按阈值。自动滚动改为等待实际滚动发生，再离开边缘、拖到明确的目标行，独立核对完整顺序；不再在滚动过程中读取可能变化的内部落点作为期望值。

新增事件循环延迟场景及长按触发前松手、Esc、失焦、退出管理模式的取消验证。本轮本地 Linux / Qt offscreen 全量 **79 项通过**；构建脚本的“测试失败则停止打包”检查保持不变。新增 Windows / Python 3.11 的 GitHub Actions，使用锁定依赖执行全量测试并重复拖动用例 5 次，执行结果以对应 PR 的 `Windows tests` 检查为准。Windows 自动化不等同于实体电脑和 exe 的人工验收。
