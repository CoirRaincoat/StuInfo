## 已修复的具体问题

| 问题 | 证据与影响 | 处理 |
| --- | --- | --- |
| 导出目标保护不完整 | 独立测试中可将 JSON 写到 SQLite journal / wal / shm、`app.lock`、`settings.ini`，可能破坏运行保护或设置 | 所有导出复用公共路径保护；文件不存在时也保留这些名称，PNG 同样检查 |
| 截断 JPEG 可通过格式检查 | `Image.verify()` 接受一张被截断的虚构 JPEG，完整像素读取却失败 | 校验增加完整解码，合法照片保持原字节；损坏导入与恢复均不提交 |
| 管理重排重复解码照片 | 优化前 100 份带照片的虚构档案移动一次，发生 100 次图片打开，约 0.5 秒，尚未计入 GUI 刷新 | 克隆已经验证的内存链表，保留候选隔离及容量检查；外部载荷、导入和最终管理提交仍完整验证；dirty 检查不再深复制整个快照 |
| 统计只能看数值 | 图表没有通往对应好友的入口；同名占位文案容易混淆类别 | 统计与明细共用年龄、兴趣和缺失信息定义；点击通过分类索引和真实分类键定位，再用 UUID 打开好友 |
| 筛选难以复用 | 反复输入同一组条件 | 常用视图保存到本地设置，保护草稿，不保存好友副本 |
| 交互反馈与命名不一致 | 侧栏“分组”实际管理多标签；成功提示长期占据工作区 | 可见文案统一“标签”，成功提示自动收起，切换页面移除过期通知；补基础表单辅助阅读名称 |
| PyInstaller 打包启动失败 | Windows 原生源码窗口正常，但 exe 的 QtCore 导入失败；复现发现构建机 PATH 中 Poppler 的 ICU 被误收集并遮蔽系统运行库 | 打包限定 DLL 搜索目录并移除不属于固定 PySide Windows wheel 的外来 ICU；动画回归断言改为等待实际状态。最终目录版 exe 两次启动通过，虚构档案及顺序未变化 |

## 本轮功能交付

1. 统计图与图例联动高亮、精确提示、鼠标和键盘查看分类好友。
2. 柱状图与环形图首次入场、轻量悬停动效，窄布局图例自动下移，减少动态效果设置立即生效。
3. PNG 导出包含最终图形、完整图例、日期、范围与口径；使用原子写入，失败保留原目标文件；过大图像明确拒绝。
4. “资料检查”统计与概览入口，可直接找到缺失信息的好友。字段仍可全部留空，多项统计允许重叠，不打分、不补造信息。
5. 最多 20 个命名常用视图，支持保存、应用、更新和删除；设置损坏或保存失败会反馈，不影响档案数据库。

自定义属性、多联系方式、多标签、收藏、管理草稿、拖放、搜索排序、合并、回收站、JSON 导入导出、完整备份恢复及链表教学入口继续保留。

## 后续值得做的功能（本轮未实现）

| 优先级 | 方向 | 需要先解决的设计问题 |
| --- | --- | --- |
| 高 | 全库重复候选工作台 | 用姓名/联系方式辅助索引形成候选，明确命中理由，仍逐次人工合并；避免 O(n²) 全比较 |
| 高 | CSV 导入预览与字段映射 | 不同联系方式列、日期含义、重复导入 ID、编码和公式注入保护；先预览再确认，不自动猜日期 |
| 中 | 备份历史与定期提醒 | 显示真实备份时间、位置与可读性，清楚区分提醒和已执行备份；保留策略需由用户控制 |
| 中 | 可撤销的管理步骤 | 限定会话内撤销和内存上限，避免每步复制所有照片；与“取消整个管理会话”区分 |
| 中 | 大规模列表模型与延迟头像缓存 | 先测量实际瓶颈；Qt 模型仅作视图适配，不替代业务链表；缓存随记录版本失效 |
| 可选 | 创建/更新时间与联系记录 | 新增时间必须从今后真实操作记录；旧档案只能标为未知，联系行为要用户明确录入 |

本轮未增加在线同步、自动清理、猜测生日或用查看档案冒充联系记录。后续功能适合按以上依赖逐步实现，而不是仅增加导航和按钮。
